# PostgreSQL Setup

Run these from the package root, in this order. `SELF-HOSTING.md` explains each step and every `.env` value.

1. `npm run setup:db` completes `.env` and then connects as a PostgreSQL administrator and creates the database `DB_NAME` and the user `DB_USER` with the password `DB_PASSWORD`. It creates no tables. `setup.mjs` first runs `environment.mjs`, which copies `.env.example` to `.env` when there is none and generates `DB_PASSWORD`, `BETTER_AUTH_SECRET`, and `DATABASE_URL` where they are empty; it then runs `setup.sh` on Linux and macOS and `setup.ps1` on Windows, which both apply `setup.sql`.
2. `npm run migrate` connects as `DB_USER` through `DATABASE_URL` and applies every migration in `migrations/` in one transaction, so `DB_USER` owns every table. On a new database it then loads `data.sql` if the download includes data. Every run also applies the `upkeep.sql` of the last step of the newest migration and verifies the whole layout against the migrations.
3. `npm run setup:auth` creates the administrator account, with a generated password when `ADMIN_PASSWORD` is empty.

`setup:db` and `migrate` are re-runnable. `setup:db` keeps an existing database and user, resets the user's password to `DB_PASSWORD`, and hands existing tables to `DB_USER`. `migrate` records applied migrations in `schema_migrations` and the layout version in `schema_shape`, and applies only new migrations.

Each migration folder holds one or more step folders, applied in order, each with `up.sql` (before the data transforms), `backfill.json` (the data transforms), `finalize.sql` (after them) and `upkeep.sql` (platform tables and column defaults); beside them the release folder holds one `convert-*.sql` per earlier layout version (the one-time conversion of a database recorded at that version, `convert-unstamped.sql` for one from before layout versions), `reconcile.sql` (which brings a database set up by an earlier download of the release to this package's columns, checks, unique indexes, and reference keys) and `schema.json` (the tables the release declares). `migrate.mjs` evaluates the transforms with `migration-backfill.mjs` and calls the functions of `migration-helpers.sql`.
